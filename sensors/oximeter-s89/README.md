# Oximeter S-89 — открытый BLE-протокол и reference client

Пульсоксиметр **S-89** (Veepoo / Goodix OEM, приложение **Oximeter-H**) — BLE-датчик
на палец: SpO₂, пульс, HRV, перфузионный индекс. Штатное приложение умеет только
показывать цифры; облако и аккаунт не нужны.

Мы восстановили рабочий протокол по живым кадрам и статическому разбору
**Oximeter-H 1.4.2** (без запуска APK на телефоне) и публикуем reference-клиент,
парсер и заметки по интеграции. Отдельного открытого описания именно S-89,
насколько мы знаем, раньше не было.

> **Не медицинское изделие.** S-89 — бытовой оксиметр. Числа ниже — то, что
> приходит с датчика; это не диагноз и не замена PSG/клиническому прибору.

## Что уже работает

- поиск датчика по имени **S-89** и сервису **0x90EA**;
- подключение к **F1080001**;
- notify **F1080002**, write **F1080003**;
- старт измерения 20-байтовым кадром **`90 02 01 00 ...`**;
- разбор SpO₂ `[4]`, пульса `[5]`, HRV `[6]`, PI `[7] / 10`;
- признак «надет/измеряет» `[3] == 1`;
- **батарея**: команда `90 01 02`, живой ответ `90 01 02 01 00 04` — это
  **4 деления из 4**, то есть 100 %, а не 4 %; клиент пересчитывает `raw*25`;
- **PPG/ADC**: F1020002, два канала `[2]=4` и `[2]=5`, по 5 сэмплов × 3 байта;
  сырые значения уже снимаются (`--ppg`);
- автоматический перезапуск замера после потери пальца.

Чего **нет** (честно):

- температуры — в `DetectData` S-89 её нет;
- готовой PPG-волны в HA — сырые F102-сэмплы есть, но `convert_ecg_value`
  и график ещё не перенесены;
- хранения истории — только live-поток.

## Быстрый старт (Windows / Linux / macOS)

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: . .venv/bin/activate
pip install -r windows/requirements.txt

# 1) посмотреть, что рекламируется
python windows/s89_reader.py --scan 20

# 2) либо явно указать MAC (подставь свой)
python windows/s89_reader.py --mac AA:BB:CC:DD:EE:FF --seconds 30
```

Скрипт сам находит S-89 по имени, подписывается на notify, отправляет старт и
печатает каждый валидный кадр. При выходе отправляет stop.

## Протокол в двух строках

```
write F1080003: 90 02 01 00 00 ... 00   (20 байт)
notify F1080002: 90 02 03 01 63 45 d2 b7 ...
                   │     │  │  │  │  └─ PI × 10 = 18.3 %
                   │     │  │  │  └──── пульс = 0x45 = 69
                   │     │  │  └─────── SpO₂ = 0x63 = 99 %
                   │     │  └────────── 1 = палец/замер
                   │     └───────────── 3 = измерение
                   └─────────────────── заголовок 0x90
```

Полный разбор, UUID, ориентация UUID в ESP-IDF, ошибочная команда IH018 и
образцы кадров — в [`docs/PROTOCOL.md`](docs/PROTOCOL.md).

## Home Assistant / ESP32

- `esp32/s89_protocol.c` — чистый C: собрать start/stop, разобрать кадр.
- `homeassistant/s89_mqtt.yaml` — готовые сенсоры SpO₂, пульс, HRV, PI, «надет».
- В нашем шлюзе R4sGate (ESP32-C3) S-89 уже подключён именно так: F108 + `90 02 01`,
  данные уходят в `mks/oximeter/state`, затем в HA/PostgreSQL.
- Если делаешь свой шлюз: не отправляй S-89 команду `80 01 02` — это протокол
  IH018/F008, он к этому прибору не относится.

## Приватность

В репозитории только наши наблюдения и собственный код. APK, чужие библиотеки,
реальные MAC-адреса и персональные данные не публикуются; в примерах стоит
`AA:BB:CC:DD:EE:FF`. Проект описывает **свой** прибор и локальную интеграцию.

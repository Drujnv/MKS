# Mi Band 1A: BLE-протокол (то, что реально используется)

Основано на открытом проекте
[`freezed-or-frozen/pymb1a`](https://github.com/freezed-or-frozen/pymb1a) (GPLv3)
и нашем разборе `analysis/miband_1a.py`. Это **не** официальная документация Xiaomi.

## Сервис и характеристики

Сервис: `0000fee0-0000-1000-8000-00805f9b34fb`

| UUID | Назначение |
|---|---|
| `0000ff01` | служебная информация |
| `0000ff03` | уведомления, ответ авторизации |
| `0000ff04` | `UserInfo` (write, 20 байт) |
| `0000ff05` | управление (команды) |
| `0000ff06` | текущие шаги (read) |
| `0000ff07` | история активности (notify) |
| `0000ff0a` | дата/время |
| `0000ff0c` | батарея (read) |
| `0000ff0e` | живой акселерометр (notify) |
| `0000ff0f` | pairing |
| `00002a06` | Alert (тап/вибро) |

## UserInfo: 20 байт в FF04

```
[0..3]  uid (uint32 little-endian; в pymb1a — java_hash(alias))
[4]     gender
[5]     age
[6]     height, см
[7]     weight, кг
[8]     which_hand
[9]     feature (для 1A = 5)
[10]    appearance (для 1A = 0)
[11..18] alias, 8 байт ASCII
[19]    CRC8(байты 0..18) XOR (последний байт MAC)
```

CRC — **Dallas/Maxim, отражённый полином 0x8C, init 0**, а не «CRC-8 poly 0x07».
Именно на этом была главная ошибка: браслет молча игнорировал `UserInfo`,
и авторизация «не отвечала».

Пример на Python:

```python
def crc8(data):
    crc = 0
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = ((crc >> 1) ^ 0x8C) if (crc & 1) else (crc >> 1)
    return crc
```

Ответ авторизации приходит на `FF03`:

- `0x05` — успех;
- `0x06` — отказ;
- пусто — `UserInfo` не принят (CRC/MAC/пароль/сопряжение).

## Батарея FF0C

10 байт; используется:

- `[0]` — уровень, %;
- `[7] | [8] << 8` — циклы;
- `[9]` — статус.

## Шаги FF06

Little-endian целое (в pymb1a — 4 байта).

## История активности

1. Подписаться на `FF07` (и, по pymb1a, на `FF06`).
2. Записать в `FF05` один байт `0x06`.
3. Приходит поток; заголовок 11 байт:

```
[0]    0x01
[1]    год - 2000
[2]    месяц - 1
[3]    день
[4]    час
[5]    минута
[6]    секунда
[7..8] ?
[9..10] blocks (uint16 little-endian)
```

4. Далее `blocks * 3` байт: `activity, intensity, steps` на минуту.
5. Подтверждение — кадр `0x0A` + поля заголовка + `~transferred` (16 бит)
   обратно в `FF05`. В pymb1a подтверждения отправляются пачкой после
   заголовка с `transferred == 0`.

## Живой акселерометр

- старт: `FF05 <- 0x12 0x01`;
- данные: notify `FF0E`, 6 байт на ось;
- стоп: `FF05 <- 0x12 0x00`.

## Pairing

- `FF0F <- 0x02` — запрос сопряжения;
- `2A06 <- 0x02` — вибрация/алерт, чтобы владелец нажал на браслет;
- окно нажатия — около **5 секунд**;
- после SMP браслет принимает `UserInfo`;
- **bond не удалять**: после сброса именно сохранённый bond держит SMP;
  удаление bond давало `SMP fail / reason 19` и ухудшало ситуацию.

## Что не отдаётся

- пульс — у 1A нет пульсометра;
- SpO2 — нет;
- сон как медицинская стадия — нет; можно анализировать только
  активность/интенсивность и историю шагов.

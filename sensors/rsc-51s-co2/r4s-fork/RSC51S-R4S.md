# RSC-51S в форке `alutov/ESP32-R4sGate-for-Redmond`

RSC-51S — **штатное Redmond-устройство** этого форка. Отдельный патч для
подключения станции не нужен: в прошивке уже есть BLE-клиент Redmond и
GATT-профили для станции/розетки.

## Что делает форк

1. Сканирует эфир и находит RSC-51S по рекламе/имени.
2. Подключается по GATT (NUS-подобные сервисы Redmond).
3. Проходит сопряжение (Just Works) и подписку на notify.
4. Отдаёт данные в веб-UI и MQTT/Home Assistant по правилам форка.

## Что важно при настройке

- **Сопряжение обязательно** — без пары станция отклоняет запись;
- **Сначала notify, потом команды** — иначе первые кадры теряются;
- первые **10 минут** после включения — прогрев, данные не использовать;
- дальность **3–5 м**, металлизированное остекление не пробивает;
- один BLE-адаптер: не держите одновременно GATT к станции и к другим
  Redmond-устройствам, если форк этого не умеет; у C3 — несколько соединений.

## Наш вклад в базу alutov

Мы используем форк как основу R4S-шлюза и добавили в своей ветке:

- отдельный декодер **Prestigio PTH01BT** (см. `../prestigio-pth01bt/`);
- профиль **SleepDot** и MQTT-команды сна (в работе);
- документацию и проверки по датчикам.

Мы **не меняли** протокол RSC-51S в upstream — он уже поддержан. Если готовить
PR в `alutov/ESP32-R4sGate-for-Redmond`, логично добавить:
1. `docs/` с картой протокола RSC-51S и правилами прогрева;
2. опциональный декодер Prestigio (отдельным файлом, без жёсткого MAC);
3. примеры MQTT/HA.

Черновик обращения к автору — `UPSTREAM.md`.

## Проверка

1. В UI R4S станция должна появиться как Redmond-устройство;
2. MQTT: подпишитесь на топики форка (`r4s0/...`) и проверьте CO₂;
3. HA: сущности CO₂/температуры/влажности, если включён discovery;
4. GATT к станции открывайте только на время проверки, потом закрывайте.
